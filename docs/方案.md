# R_N 资料库 · 总体方案

> 定稿于勘察阶段。本文是设计的唯一权威来源，实现与之冲突时以本文为准。

## 一、背景与目标

`E:\01-personal-database` 从零建设，用于存放个人文档资料（**以 PDF /
Word / PPT / Excel 办公文档为主**），部署到 Netlify，供三处使用：

| # | 需求 | 落点 |
|---|---|---|
| ① | 网页流畅观看 + 下载 | 预生成预览件 + 流式下载 |
| ② | 公用接口对接工作站与博客 | 带版本的只读 REST API |
| ③ | AI + 分类快速定位文档 | 受控词表 + 自动打标 + 全文检索 |

已确认的前提：资料库**目前是空的**，要**从零积累**；**私有**，需密码访问；
AI 深度先做到**全文检索 + 标签分类**这一层。

## 二、勘察结论（已核实，非推测）

| 项目 | 可复用的结论 |
|---|---|
| `01-private-gallery` | Netlify Blobs + `auth-config`(SHA-256) 门禁；Functions v2 用 `config.path` 声明路由（无需 redirects）；`X-Auth-Token` / `?token=` 双通道 |
| `01-personal-blog` | `_shared/cors.ts` 的 `ALLOWED_ORIGIN` 白名单模式；`gallery-list.ts` 是现成的跨项目调用先例；响应契约 `{status,message}` |
| `01-smart-workstation` | `packages/gallery` 已用 `DEFAULT_BASE='https://r-gallery.netlify.app'` + `X-Auth-Token` 消费 Netlify 站点 —— **这条路已经跑通** |
| `01-smart-workstation` | `packages/mcp-server` 把 `ctx.tools.list()` 的**全部工具自动暴露为 MCP 工具** → 新增模块只要注册工具，AI 立刻可用，**无需另写 MCP server** |

环境实测：Node v24.18.0；`Intl.Segmenter` 中文分词可用
（`这是一份关于报销的发票` → `这|是|一份|关于|报销|的|发票`）；
`gh` CLI 已装未登录；GitHub 账号 `raven-null` 走 SSH；LibreOffice 未安装。

## 三、存储分层

Blobs store 划分（`netlify/functions/_lib/store.mjs` 中集中定义）：

| Store | 内容 | 为什么独立 |
|---|---|---|
| `doc-files` | 原件 | 唯一真相，下载走这里 |
| `doc-previews` | 预览件（PDF） | 观看体验不依赖浏览器兼容性 |
| `doc-text` | 抽取正文（`<id>.json`） | 检索与 AI 的数据源，与原件解耦 |
| `doc-meta` | 每份文档元数据 | 列表页只读它，不碰大文件 |
| `doc-index` | 倒排索引 + 分类树 + 标签表 | 整包下发前端，检索零函数调用 |
| `doc-auth` | 密码哈希 + 令牌表 | 沿用图库做法 |

**文档 id = 内容 SHA-256 前 12 位** → 天然去重。

## 四、需求 ①：流畅观看 + 下载

**观看体验的关键在入库预处理，不在前端。** 浏览器原生只渲染 PDF，
docx/xlsx/pptx 直接打开就是下载或乱码。

预览策略（按优先级）：

1. **LibreOffice 无头模式 → PDF**（保真度最高，PPT/复杂排版可还原）
   `soffice --headless --convert-to pdf`
2. **HTML 降级**（未装 LibreOffice 时）：docx→mammoth、xlsx→exceljs、
   pptx→抽取文本 + 幻灯片图。PPT 保真度明显下降。
3. **Office Online Viewer**（`view.officeapps.live.com`）：保真度高、
   零本地依赖，**但文档会被发送到微软服务器** —— 对合同/票据这类
   私有资料是真实的隐私取舍，默认不启用。若启用需配短期签名 URL。

其他实现要点：

- PDF 用 `<iframe>` 内嵌，浏览器原生渲染器负责翻页缩放
- 下载用 RFC 5987 编码中文文件名
  （`filename*=UTF-8''...`，否则下载下来是乱码）—— 已在 `respond.mjs` 实现
- 元数据与文件分离：首屏不下载任何文件
- 预览件内容寻址 → `immutable` 长缓存

## 五、需求 ②：公用接口

### API 契约（`/api/v1`，冻结后不轻改）

```
GET  /api/v1/health                     探活与自检（免鉴权，不泄密）
GET  /api/v1/docs?q=&category=&tag=&type=&sort=&page=&limit=
GET  /api/v1/docs/{id}                  元数据
GET  /api/v1/docs/{id}/text             抽取正文（给 AI 用）
GET  /api/v1/docs/{id}/file             原件（attachment）
GET  /api/v1/docs/{id}/preview          预览件（inline）
GET  /api/v1/search?q=&limit=           服务端全文检索（带高亮片段）
GET  /api/v1/taxonomy                   分类树 + 标签表
GET  /api/v1/manifest                   全量元数据 + indexVersion + ETag
POST /api/v1/auth/login                 换 token
```

统一响应：成功 `{ ok: true, data }`，失败 `{ ok: false, error: { code, message } }`。

**为什么统一并加版本号**：要消费它的有三方，而你现有两个项目契约不一致
（博客 `{status,message}`、图库 `{error}`）。新项目被多方依赖，必须先冻结
一套再往外发，版本号保证日后演进不会把工作站和博客一起打挂。

### 鉴权：三档令牌，只存 SHA-256

| 令牌 | 权限 | 给谁 |
|---|---|---|
| `admin` | 读写删 | 只有你自己 |
| `read` | 只读全部 | 工作站、博客 |
| `guest` | 只读标记公开的 | 日后对外 |

三种传输通道覆盖不同场景：

1. `X-Auth-Token` 头 —— API 调用
2. `?token=` 查询参数 —— `<iframe>`/`<img>` 无法自定义请求头
3. `?exp=&sig=HMAC` 短期签名 URL —— 交给第三方抓取，避免长期令牌进 URL

### 工作站接通

在 `01-smart-workstation` 新增 `packages/database/`，仿 `packages/gallery`
写法，注册工具：`docs_search` / `docs_list` / `docs_get_text` / `docs_download`。

**注册完即自动出现在 MCP 工具列表**（`mcp-server` 遍历 `ctx.tools.list()`），
AI 立刻能查资料库，零额外工作。这是本方案性价比最高的一环。

工作站是 Tauri 桌面端、从 Node 侧调用，**不受 CORS 限制**。

### 博客接通

仿 `gallery-list.ts` 加 `docs-list.ts` + 资料页。博客在浏览器里跑，
**必须**把域名加进 `ALLOWED_ORIGIN`。

## 六、需求 ③：分类 + AI

### 分类体系：受控词表

定义约 10 个一级分类（合同证照 / 票据财务 / 学习资料 / 项目文档 /
说明书 / 健康医疗 / 生活杂项…）+ 标签表。

**AI 只能从词表里选，选不中则上报新词进「待整理」队列，不允许自己造词** ——
否则三个月后分类会腐烂成一堆同义词。数据结构沿用图库已验证的
`categories: string[]` + `tags: string[]`。

### 入库流水线（`scripts/ingest.mjs`）

```
扫描文件夹
  → SHA-256 去重
  → 抽元数据（标题/作者/页数/创建时间）
  → 抽正文：pdfjs-dist(PDF) · mammoth(docx) · exceljs(xlsx) · XML(pptx)
  → 生成预览件（LibreOffice → PDF）
  → AI：正文前 N 千字 → 摘要 + 建议分类 + 建议标签
  → 直写 Blobs（doc-files / doc-previews / doc-text / doc-meta）
  → 重建倒排索引 → 写 doc-index
```

`exceljs` 而非 `xlsx`：npm 上的 `xlsx` 版本陈旧且有安全公告。

### 检索：索引下发前端，检索零函数调用

- 用 **`Intl.Segmenter`（`granularity:'word'`）做中文分词**构建倒排索引 ——
  Node 20+ 与浏览器都原生支持，**零依赖**，不必引 jieba 之类的重库
- 索引随 `/api/v1/manifest` 带 `indexVersion` + ETag 下发，前端缓存
- 前端 MiniSearch/FlexSearch 做即时全文搜索，配 `pinyin-pro` 支持拼音搜中文
- 服务端 `/api/v1/search` 作兜底

**为什么不先上向量库**：全文 + 标签已能覆盖「快速找到文档」，且前端检索
零函数调用、零延迟、省配额。语义检索与 RAG 问答留二期 ——
`GET /docs/{id}/text` 正好是未来 embedding 的输入源。

## 七、刻意的设计决定（与图库项目的差异）

1. **线上禁止静默回退本地存储** —— 否则 Blobs 未启用时会「入库成功但数据蒸发」
2. **线上未配密码 = 拒绝所有访问**（fail-closed）—— 图库是放行，对私有库太危险
3. **不在 Netlify 配 SITE_ID / Access Token** —— 运行时自动注入，显式配置等于
   把全站令牌塞进构建环境
4. **构建命令做真校验而非 echo 占位** —— Git 自动部署下每次 push 都影响线上
5. **公开仓库 → 构建期密钥泄漏扫描** —— 拦住 .gitignore 漏项与硬编码密钥

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 同步函数响应体积上限（约 6MB，**待实测**） | 原件/预览件走流式 Response |
| Blobs 单对象上限（**待实测**） | 办公文档体积小，风险低 |
| Office 在线预览需公网可访问 | 优先本地转 PDF；必须用时走短期签名 URL |
| 中文文件名下载乱码 | RFC 5987 编码（已实现） |
| Blobs 无原生 Range | 小文件整发；大 PDF 流式 + 手动 Range |
| 大 PDF 首屏慢 | 入库时生成低分辨率快开版 |
| Deploy Preview 可公开访问 | 自带门禁仍生效；介意则在 Netlify 关掉预览 |
| 带宽/调用配额 | manifest 客户端缓存 + 预览件 immutable |
| 分类被 AI 自由生长撑烂 | 受控词表 + 待整理队列 + 人工确认 |
| 单文件膨胀难维护 | 一开始就 ES 模块拆分（图库 270KB app.js 的教训） |
| 误删无备份 | `export.mjs` 全库导出 + 元数据快照 |
| 公开仓库泄密 | `check.mjs` 密钥扫描 + .gitignore 校验 |

## 十、明确不做

- ~~不做在线编辑（只读归档，编辑走本地）~~ —— **已改为支持**，但只针对
  纯文本类（代码 / Markdown / 纯文本）。Office 与 PDF 是二进制容器，
  网页里的 textarea 改不了结构，那些类型仍然「重新上传」。
  详见 11.8
- 不做多用户/协作/权限体系（一个人用，三档令牌足够）
- 一期不做 embedding / RAG 问答（接口已预留）
- **不做任何代码执行**：能存、能改、能看，但永不运行。
  这是刻意的边界 —— 一旦执行，静态站就变成了别人的计算资源
- 不做视频/大文件流媒体。日后若真要存视频，正确做法是换
  Cloudflare R2 / B2 做存储层，Netlify 只做前端与 API ——
  架构上 `doc-file.mjs` 是唯一改动点

## 十一、实施记录（与初版方案的偏离）

方案是设计的起点，实施中被实测数据推翻的地方都记在这里，
避免后人照着过时的描述去改。

### 11.1 索引从单文件改为分片（性能）

初版把整个倒排索引放在**一个** blob 里。256 份文档时已 6.23MB，推算 1000 份到 24MB。
实测每次检索都要读全量：`search` 134–149ms，`manifest` 为了取个版本号也白读 6MB。

改为按词条哈希分 **128 片** + 独立的 `index-meta` 后：

| 端点 | 改前 | 改后 |
|---|---|---|
| search「配置」 | 149ms | 34ms |
| search「协议」 | 134ms | 24ms |
| manifest | 254ms | 54ms |

检索只读查询词所在的 1–11 片。

### 11.2 分类：同形词是主要误差来源

256 份文档实测出 5 例误判，全是**技术语境下的同形词**：
「协议」把交互协议打成合同证照、「诊断」把 diagnostics 打成健康医疗、
「流水」把事件流打成票据财务。

关键判断：这些词在**真实语料（合同/票据）里恰恰是最强信号**，暴力降权会误伤。
区别在于出现在**标题还是正文** —— 合同会被命名为「XX协议」。
因此折扣只作用于正文命中，标题命中保持满分。

**否决的方案**：曾想用 `Intl.Segmenter` 判断关键词是否作为独立词出现。
实测分词器把「流水线」切成 `["流水","线"]`、「诊断信息」切成 `["诊断","信息"]`
—— 同形词在两种语义下都是独立词，**分词无法消歧**。词义消歧只能靠策展词表或 LLM。

另有一个概念错误值得记录：第一版把**泛词**（配置/参数/架构/接口/部署）
也当同形词打折，结果大量技术文档从「技术参考」掉成「未归类」。
泛词该用跨分类 spread 折扣，不该用同形词折扣。

### 11.3 ASCII 必须按词边界匹配

标签「AI」按子串匹配时，`email`、`available`、`explain`、`detail` 全部命中
—— 256 份里 243 份被打上「AI」标签。关键词层同理（「api」会匹配 `rapid`）。
改为词边界后降到 124。

### 11.4 打分从「命中数 × idf」改为 BM25

初版没有词频、没有长度归一化，导致「提一次」与「通篇都是」在数学上没区别：
搜「操作系统」时，只在技能栏提了一次的简历与整篇讲操作系统的课件**同分 2.30**。
改 BM25 后变成 0.87 / 0.76 / 0.41，排序正确。

### 11.5 新增的能力（方案里没写但必须有）

- **写操作**：`PATCH` / `DELETE /api/v1/docs/{id}`。没有它，
  `needsReview`「待复查」队列就是死胡同 —— 机器分错了你只能干瞪眼。
  索引走**增量更新**（只读改写受影响分片），不重建全库。
  写操作要求 admin 令牌，read 令牌（工作站/博客）不能改资料。
- **批量任务不覆盖人工策展**：`reclassify` 会跳过标了 `manual` 的文档。
  否则你在网页上改好的分类，一次批量重跑就被冲掉。
- **拼音检索**：入库时把拼音算好存进元数据，前端零依赖 ——
  省掉了图库项目在浏览器端加载的 315KB pinyin-pro。
- **测试体系**：分类回归（面向真实办公文档，与语料无关）、写操作回归、
  内容编辑回归、增量索引单元测试、前端 jsdom 冒烟、真实浏览器渲染检查（CDP）。
  其中渲染检查是为了验证「元素没塌陷、CSS 生效」这类 jsdom 查不出的问题。

### 11.6 仍待处理

  端点已可配置（任意 OpenAI 兼容），可复用工作站的 `STATION_LLM_*`。
- **工作站与博客尚未接入**：API 这一侧已完成并验证。
- **导出/备份脚本还没有**：目前全库数据只存在于 Blobs（本地是 `.local-data/`），
  而 `node scripts/reset.mjs --yes` 是可用的。策展（分类/标签/编辑过的内容）
  是**不可再生**的，必须尽快补一个 `export.mjs`。
- **库是空的**：测试语料已按需清空，等待真实资料入库。

### 11.7 环境约束（踩过的坑，写给后来者）

- **不要用 PowerShell 的 `Get-Content` 处理含中文的源文件**：
  该环境会按 GBK 读 UTF-8，中文变乱码，且多字节序列会**吞掉换行符**
  导致结构损坏。这个错误犯了两次。读文件用 read 工具。
- **`git commit -m` 带中文引号会崩**：提交信息里的 `["流水","线"]`
  被 PowerShell 当成语法。改用 `git commit -F <文件>`。
- **沙箱禁命名管道**：SSH 与 headless Chrome 的 Mojo IPC 都因此失败，
  需要一次性放宽权限。
- **Node 的 child_process 用管道捕获输出会 EPERM**：用 `stdio:'ignore'`。
- **测试不要写死语料**：冒烟测试原先写死了「简历第一版」等标题，
  库从 3 份变 256 份后全崩。改为用真实 manifest 数据驱动断言。
  后来更进一步：前端测试**自己造夹具**（`scripts/lib/fixtures.mjs`），
  跑完即删 —— 否则「按需清空测试数据」之后整套前端测试就再也跑不起来。

### 11.8 代码存储与网页内编辑

需求追加：「我还需要能存代码，不需要运行就是能存能编辑」。

**存什么**：约 60 种代码/配置后缀归一为 `type: 'code'`（见
`_lib/file-types.mjs` 的 `EXT_ALIASES`），MIME 统一 `text/plain`。
预览件是带行号 + 语法高亮的 HTML（`_lib/code-view.mjs`，服务端渲染，
前端零依赖，CSP 仍是 `default-src 'none'`）。

**怎么改**：`PUT /api/v1/docs/{id}/content`，只允许 `code / md / txt`。
一次编辑要同步五处，少一处都是**静默错误**：

| 环节 | 漏掉的后果 |
|---|---|
| 原件 `doc-files` | 下载到的还是旧文件 |
| 正文 `doc-text` | `/text`、AI、检索全部读旧内容 |
| 预览件 `doc-previews` | 预览停在旧内容，用户以为没保存上 |
| 元数据（sha/size/字数） | 列表信息与实际不符 |
| 倒排索引 | 旧词永远搜得到、打开却看不到 |

三个关键决定：

1. **id 不随内容变**。id 是入库时的内容哈希，但它是 URL、标签、
   外部引用（工作站/博客）的锚点，换 id 等于让所有引用失效。
   代价：`/file` 不能再标 `immutable`，改为「URL 带 `?v=` 才允许长缓存」。
   这一条是编辑功能上线时**必须同步改**的，否则浏览器会抱着旧文件一整年。
2. **旧正文必须在覆盖前读出来**。索引增量更新要用新旧两版正文算词频差。
   同一条理由也适用于**删除**：原先 `removeDoc` 先删正文 blob 再更新索引，
   算出来的旧词频只剩元数据部分，正文独有的词永久残留在分片里。
   这个 bug 一直存在，是写内容编辑时才顺带发现的（见 `test-index-delta.mjs`
   里保留的「反例」断言）。
3. **编辑区就是朴素 textarea**。富文本编辑器会把 Tab 变空格、吃掉行尾空白、
   把 `&` 转成实体 —— 存回去的就不是原来那个文件。只补三件必需的事：
   Tab/Shift+Tab 缩进、Ctrl+S 保存、有未保存改动时拦一下关闭。
   外加乐观并发（带 `baseUpdatedAt`，冲突返回 409），避免两个标签页互相覆盖。

**两个只有真渲染才能发现的问题**（都由 `render-check.mjs` 抓到）：

- 行号列比代码块高一个行高：文件末尾的换行是终止符，`split('\n').length`
  会多算一行，于是最后一个行号孤零零挂在代码下面。修法是 `countLines()`
  （`_lib/plain-text.mjs`），前后端各留一份等价实现。
- 行号与代码的对齐依赖「两边 padding-top 与行高完全一致」—— 这一点已写成
  真实浏览器断言，改样式时会立刻报出来。

### 11.9 Office 三件套：不转 PDF 也能看

需求追加：「Word、Excel、PowerPoint 有没有不变成 PDF 就是正常的展示」。

先分清三种格式，它们的最优解完全不同：

| 格式 | 结论 | 做法 |
|---|---|---|
| Excel | **网页表格明显更好用** | 入库时解析成结构化模型，前端画成表 |
| Word | 可行，保真度够用 | docx-preview 在 jsdom 里渲染成静态 HTML |
| PowerPoint | **不建议替换 PDF** | pagus 渲染成内联 SVG，作为可选的实验档 |

**为什么 Excel 最值得做**：表格是数据不是版式。PDF 里要缩放拖拽、手机上没法看、
复制出来是碎行。结构化之后：表头吸顶、首列冻结、能滚动、能整块复制，
浏览器自带搜索也照常好用。而且解析只要 7ms，比转 PDF 快两个数量级。

**为什么 PPT 不替换 PDF**：幻灯片是绝对坐标摆版式，开源实现很难复刻
PowerPoint 的排版引擎。实测（3 张夹具幻灯片，形状/表格/图片齐全）：
文字内容与 Office 导出的 PDF **逐条一致**，元素齐全、坐标都在界内，
但字体度量与换行位置有差异 —— 对"看内容"够用，对"看版式"不够。
所以 PPT 默认仍是 PDF，网页版放在第二位并标注"实验"。

**产品形态：双档，不是替换**。阅读页顶部切换，按 `webView` 记住选择：

- Word：先给网页版（手机友好、可复制），原始版式在后
- Excel：先给表格，原始版式在后
- PowerPoint：原始版式在前，网页版（实验）在后

为此新增两类预览件（都仍由入库脚本在本地生成，线上只读）：
`<id>.web.html` / `<id>.slides.html` / `<id>.sheet.json`，
接口是 `/preview?view=web|sheet`。

**明确不做的两条路**：

- **Office Online / Google Docs Viewer 嵌入**：它们要求文件能被公网抓取。
  私有资料库为了渲染一份文档把内容交给第三方，不划算；签名短链只是
  缩小泄漏窗口，没有消除。
- **浏览器内 WASM 版 LibreOffice**：体积数百 MB，静态站不现实。
  顺便记一笔：npm 上的 `univer` 是个玩笑包（0.0.5，描述就写着
  "This is a joke!"），真库在 `@univerjs/*` 作用域下 —— 装之前先 `npm view`。

**实现期踩到的三个坑**（都已被测试固化）：

1. **借 DOM 全局时不能 `bind`**。为让 docx-preview 在 Node 里跑，
   把 jsdom 的 `HTMLElement` 等挂到 globalThis；一开始做了 `v.bind(window)`，
   于是库内部的 `el instanceof HTMLElement` 全为 false，
   **整篇文档被当成空文档渲染**，页面只有空壳且不报错。
2. **不能用 `actualColumnCount` 圈范围**。实测一个带 H 列的工作簿，
   `actualColumnCount` 只报 7，H 列整列被吞掉 —— 用户会以为数据丢了。
   改为 `eachRow/eachCell` 稀疏遍历实际存在的单元格。
3. **合并单元格要去重**。ExcelJS 对合并区的每个从属格都返回主格的值，
   不处理的话同一句标题在表里出现 5 次。
4. **PPT 的 `foreignObject` 会故意超出幻灯片**。pagus 为了容纳自动行高，
   把文本框对称放大、y 可为负；位置由外层 `<g transform="translate()">` 决定。
   因此"越界检查"要查 translate，不能查 foreignObject。

顺带修掉一个标题问题：库生成的文档会把**工具名**写进文档属性
（pptxgenjs 写的内嵌标题就是 "PptxGenJS Presentation"），
它会顶掉文件名，列表页上一堆同名文件。`isJunkTitle` 增加了
生成库前缀名单（pptxgenjs / exceljs / apache poi / …）。
